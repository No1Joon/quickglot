# 결정

- Safari **Web Extension**(MV3)으로 만든다 — App Extension은 macOS 전용이고 신규 API가 전부 Web Extension으로 갔다.
- 번역은 **Apple Translation framework** 온디바이스만 쓴다 — 키·과금·네트워크 코드가 전부 사라진다.
- 최소 지원 OS는 **iOS 26 / macOS 26** — `TranslationSession(installedSource:target:)`(non-UI 생성자)이 26.0+ 이다.
- 언어 감지는 Swift **`NLLanguageRecognizer`** 로 한다 — franc 같은 JS 의존성이 필요 없다.
- 12자 미만 선택은 언어 판정 신뢰도 0.55 미만이면 거부한다 — 단어 하나는 오탐이 잦다.
- 언어팩 다운로드는 **컨테이너 앱**이 `prepareTranslation()` 으로 한다 — 시스템 동의 시트는 확장에서 못 띄운다.
- 확장은 `.installed` 인 언어쌍만 번역하고, 아니면 `notInstalled` 를 돌려준다 — 사용자에겐 "앱에서 받으세요"로 보인다.
- 번역 fetch는 background(service worker)에서만 한다 — content script 직접 호출은 페이지 CSP에 막힌다.
- 팝업은 **closed Shadow DOM** 에 그린다 — 호스트 페이지 CSS가 UI를 못 건드린다.
- macOS 트리거는 `mouseup` 즉시 번역, iOS는 `selectionchange` → 플로팅 칩 탭 — iOS는 시스템 콜아웃이 선택 제스처를 먼저 가져간다.
- 팝업은 선택 영역 **아래**에 붙인다 — iOS 콜아웃이 위쪽 공간을 쓴다.
- 팝업은 페이지 좌표에 `absolute` 로 고정하고 스크롤로 닫지 않는다 — 번역한 문장 옆에 그대로 남아야 한다.
- 배치 계산은 선택 시점에 캡처한 뷰포트 좌표로만 한다 — 번역 대기 중 스크롤해도 로딩·결과 패널이 같은 자리에 뜬다.
- 번들러는 **esbuild** — Safari 전용이라 wxt의 크로스브라우저 이점이 안 쓰이고, 파이프라인이 20줄로 끝난다.
- Xcode 프로젝트는 `dist/` 를 상대경로로 **참조**한다(`--copy-resources` 미사용) — `npm run build` 후 Xcode 빌드만 하면 반영된다.
- 네이티브 코드는 파일 하나에 몰아둔다 — 파일 추가는 pbxproj 편집이 필요해 CLI에서 비싸다.
- 성공 응답만 캐시한다 — `notInstalled` 는 사용자가 언어팩을 받는 순간 낡는다.
- 같은 언어쌍을 다시 받을 땐 `Configuration` 을 새로 대입하지 말고 `invalidate()` 한다 — `translationTask` 는 값이 달라져야 재실행돼서, 동일 값 대입은 스피너가 안 풀린다.
- 언어팩 설치 판정은 시트가 닫힌 뒤 `LanguageAvailability` 재조회로만 한다 — `prepareTranslation()` 은 다운로드 완료가 아니라 시트 dismiss 에도 리턴한다.
- 대상 언어는 확장 팝업에서 고르고 `browser.storage.local` 에 둔다 — 앱과 확장은 App Group 없이는 설정을 공유 못 한다.
- 앱의 언어팩 다운로드는 From/To 를 직접 고르게 한다 — 확장 설정을 못 읽으므로 추론하면 어긋난다.
- 선택한 글이 이미 대상 언어면 아무것도 띄우지 않는다 — 매번 에러 카드가 뜨면 고장 난 것처럼 보인다.
- 팝업의 언어 목록은 네이티브 `languages` 요청으로 받는다 — 하드코딩하면 실제 지원 목록과 어긋난다.
- `dist/` 파일이 늘거나 줄면 `scripts/regen-xcode.sh` 로 프로젝트를 재생성한다 — 개별 파일 참조라 수동 pbxproj 편집은 깨지기 쉽다.
- 로딩 패널은 200ms 뒤에 띄운다 — 같은 언어 무시(1ms 미만)와 캐시 적중은 즉시 끝나서 먼저 그리면 깜빡임만 남는다.
